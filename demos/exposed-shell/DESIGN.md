# Exposed Shell design direction

Read this as a live vulnerable-system demo for hackathon judges. It should feel like a printed field notebook left open beside a real machine console: curious, exact, and a little uneasy.

- **Palette:** warm paper and deep ink carry the workspace; chartreuse marks selection, a ready session, and the command action; orange marks the vulnerability warning and session errors.
- **Typography:** a book serif gives the notebook a human voice, system sans keeps controls familiar, and monospace stays with code and machine output.
- **Composition:** the file rail locates the work, the notebook excerpt gives it context, and the live terminal gets the largest, darkest surface because it is the demo's working core.
- **Spacing:** generous space around the title separates orientation from the working area; denser spacing inside the code and terminal keeps real output legible.
- **Identity:** notebook cell numbering and file labels connect the page to its actual project; no decorative security graphics, fake metrics, or invented claims.
- **Motion:** none by default. Session state changes are live feedback; extra animation would compete with command output.

Dial: ENERGY 3 / RHYTHM 2 / MOTION 1.
